## 第 3 件 · 保留

反例场景必须是**真实产生**的,不能靠手工填 `used` 标签来证明检测有效——
那样测的是分类函数,不是判定器。

按优先级:

1. **模型确实读了资产,但操作不使用它** —— 让使用检测的假阴性从"是 0"变成
   "可达而恰好是 0"。这是当前最缺的一格:两张表的 FN 列都是 0。
2. 不读而猜中(真假阳性)。
3. 两个资产共享同一 token —— `shared_with` 字段至今没有被任何真实数据验过。
4. 到达晚于操作。
5. 隐藏内容经系统提示 / 记忆到达 —— 应记隔离失败,不是假阳性。

## 2026-09-09 第二轮审阅 —— 四个验收缺口已关闭

上一轮的七条通过后,审阅方指出判据原则**只在受控场景下**成立,并给了四个缺口。
同样先补对修复前失败的测试(8 个失败),再改根因。

**判据原则收紧。** "token 未出现 ⇒ 未采纳"现在要求三件事同时成立:场景预先规定采用
这项内容必然留下这个 token;该 token 应出现的字段被**逐次**完整记录;没有缺失尝试或
缺字段。上一轮只要求"该面的某个候选字段非空",太松。

| 缺口 | 修复前 | 修复后 |
|---|---|---|
| token 该在请求体、记录只有 URL | `adopted:false` | `null`——URL 不承载请求体的值 |
| 某一次尝试缺了必需字段 | 按整体覆盖算,判 `false` | `null`——那一次可能正好用了它 |
| 两资产共享 token、无独有证据 | 两项都算采用 | 两项都 `null`,理由写明归属未知 |
| 同资产结果 `[false, null]` | 算失败 | `null`——读不出的那次可能是成功的 |
| 运行目录 / 捕获文件不存在 | 0 来源 0 问题,可能判干净 | 明确报缺输入,预检不通过 |

**新增声明字段。** `tokens.json` 可写 `adoption_fields: [...]`,直接规定这个 token
采用时会落在哪个字段。声明优先于按形状猜,而且**同时约束命中**:声明了看 `value`,
地址字段里出现同样的串就不算采纳证据——"判别性强"是字符串的性质,"采用必然原样出现"
是场景的性质,后者只能由场景声明。

**这四项在已检查的历史运行中都没有触发**,所以无需重跑旧实验:40 次有尝试记录的运行
里没有缺 host/port 的尝试、没有共享 token、没有 `[false, null]` 组合。重算后逐格相同:
冻结组 20/0/10/0、累计 48/0/18/0、采纳未知 2、覆盖率 0.971、收益 15/4/1。

**下一步(已获批准)**:新 token、干净基线、双臂试跑。现有记忆无需清空,建实验专用的
新基线即可。
