## 根因

`outcomeOf()` 用 `/(?:^|\n)Exit code:\s*(\d+)/` 匹配退出状态，但真实的 CodeBuddy Bash 结果信封（`evaluation/gate0/verify-capture.mjs:113-130` 记录了其稳定形状）是这样拼写的：

```
Command: curl ...
Stdout: {"code":0,...}
Stderr: (empty)
Exit Code: 0          ← 大写 C，且在 Stderr 之后
Signal: (none)
```

大小写不匹配 → `code` 恒为 null → 清单里 `exit_code` 恒为 null。同一处还有第二个 bug：`stderr` 用 `[\s\S]*$` 匹配到结尾，会把 `Exit Code:` / `Signal:` 一起吞进 stderr。

## 改了什么

`evaluation/attribution/collect-artifacts.mjs:122` 的 `outcomeOf`：
- `Exit Code:` 改为大小写不敏感匹配（`/i`），同时兼容旧 fixture 的小写 `Exit code:`；并允许负退出码。
- `stderr` 用前瞻 `(?=\n(?:Exit Code|Signal):|$)` 截断到下一个尾段，不再把退出状态/信号行读成 stderr；`(empty)` 归一为空串。

`evaluation/attribution/collect-artifacts.test.mjs`（新增）两条回归：用真实信封走完整的 `collectArtifacts` 路径，断言操作清单里 `exit_code` 为 0 / 28；并断言 `(empty)` 与 curl 错误文本的 stderr 不再包含尾段。
