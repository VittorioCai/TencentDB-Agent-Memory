## What changed and why

**`evaluation/gate/fetch-resource.mjs`** (new) — exports `fetchResource({ skillId, path, bridgeBase, fetcher })`.

- POSTs `{skill_id, path}` to `${bridgeBase}/files/read`, using `fetcher ?? globalThis.fetch` so tests need no live stack.
- On success decodes `data.content` by `data.encoding` (`base64` → `Buffer.from(content, "base64")`, else utf-8) and returns the `Buffer`, so the caller writes it straight to disk. I took this rule from the two implementations I checked: `MemoryProxy/src/skill/skill-bridge.ts` (`files/download`) and `MemoryCore/src/core/skill/skill-core.ts` (`readFile`).
- **Empty content is a legal empty file**: `content: ""` decodes to a zero-byte Buffer and returns as success. I deliberately did *not* copy the proxy's `!parsed.data?.content` check — that treats an empty resource as a failure, which is exactly the bug the task calls out. I used `?? ""` rather than a truthiness check so an empty string is never mistaken for an error.
- **Error envelope thrown, not swallowed**: `code !== 0` throws `Error("fetchResource: <envelope.message> (code N)")`.

**`evaluation/gate/fetch-resource.test.mjs`** (new) — one test, stubbed `fetcher`, covering the three required behaviors: utf-8 bytes returned and POSTed to the right URL/body; base64 decoded to raw bytes; empty content → zero-byte Buffer; error envelope → `assert.rejects` on the envelope message.
